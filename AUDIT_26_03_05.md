## 5. Codebase Architecture & Boilerplate Audit

*(Objective: Analyze each app to improve reusability, enforce Domain-Driven Design (DDD), optimize load speed via code-splitting, and drastically reduce file count.)*

### 5.1 Content & Productivity Apps (Notes, Markdown, Tasks, Checklist, Bookmarks)

**Current State:** Highly repetitive UI shells. Each app maintains its own `*Card.jsx`, `*Editor.jsx`, and local `services/*.js`.

* [x] **File Reduction (Cards):** Delete `NoteCard.jsx`, `MarkdownCard.jsx`, `TaskCard.jsx`, and `BookmarkCard.jsx`. Replace them entirely with a single, globally shared `components/ui/VaultItemCard.jsx` that accepts `title`, `date`, `icon`, and `children` props.
* [x] **File Reduction (Services):** Delete `apps/notes/services/notes.js`, `apps/tasks/services/tasks.js`, etc. Instantiate these using `services/createEncryptedCRUD.js` inside a centralized `services/collections.js` factory to enforce a single source of truth for the data layer.
* [x] **DDD & Organization (Shared Notes):** Move the floating `apps/SharedNote.jsx` into `apps/notes/components/` or a dedicated `apps/shared/` domain. It breaks domain boundaries sitting at the root.
* [x] **Speed Optimization (Markdown):** The Markdown app contains multiple viewer variants in `components/ui/` (e.g., `MarkdownViewer copy.jsx`, `MarkdownViewer copy 2.jsx`). Delete the copies. Ensure the main `MarkdownViewer.jsx` dynamically imports the markdown parsing library (e.g., `React.lazy(() => import('react-markdown'))`) so it doesn't bloat the initial application bundle.

### 5.2 Structured & Sensitive Data Apps (Banking, Finance, Passwords, Contacts)

**Current State:** Redundant list row components and complex, duplicated form state management.

* [x] **Reusability (List Rows):** `Banking` uses `AccountRow.jsx` and `CredentialRow.jsx`; `Finance` uses `FinanceRows.jsx`. Consolidate these into a generic `components/ui/SecureDataRow.jsx` that accepts a label, a masked value, and an unmask toggle.
* [x] **File Reduction (Editors):** `BankingEditor.jsx`, `FinanceFormModal.jsx`, `PasswordEditor.jsx`, and `ContactEditor.jsx` duplicate form validation and local state logic. Create a generic `components/ui/DynamicSchemaForm.jsx`. Define JSON schemas for each domain (e.g., Bank schema vs. Contact schema) and pass them to the dynamic form, eliminating the need for 4 separate editor components.
* [x] **Speed & Security:** Ensure these apps are strictly lazy-loaded via `AppRegistry.js`. Because they handle the most sensitive data, their memory footprint should only exist when the user explicitly opens them.

### 5.3 Utilities & Tracking (Counter, Reminders, Alerts, Authenticator)

**Current State:** The `Counter` app is over-engineered with 8 distinct components (`CounterDetail`, `CounterList`, `EntryModal`, `StatsView`, etc.).

* [x] **Reusability (Modals):** Merge `counter/components/EntryModal.jsx`, `counter/components/ViewEntryModal.jsx`, and `bookmarks/components/AddBookmarkModal.jsx` into a globally shared `<EntityModal>` inside `components/ui/Modal.jsx`.
* [x] **Reusability (Analytics):** Both `Finance` and `Counter` have a `StatsView.jsx` component. Move this out of the bounded contexts and into a shared `components/ui/charts/StatsView.jsx` to maintain a consistent data visualization design system.
* [x] **DDD (Authenticator):** Maintain `AuthCard.jsx` and `AuthEditor.jsx` locally within `apps/authenticator/`, as TOTP generation logic is highly domain-specific and should not bleed into the global UI components.

### 5.4 Specialized Domain Apps (Research, SecureShare, Settings)

**Current State:** Heavy, highly specific logic. `Research` has 8 sub-components, `SecureShare` handles WebRTC, and `Settings` manages 6 different tabs.

* [x] **DDD (Research App):** Keep components like `PaperAiSection.jsx`, `PaperMetadataForm.jsx`, and `PaperNotesPanel.jsx` strictly inside `apps/research/`. This is excellent Domain-Driven Design. However, implement strict code-splitting here: AI processing and PDF rendering dependencies must be chunked separately to maintain vault speed.
* [x] **DDD (SecureShare):** Ensure `hooks/useWebRTC.js` is only imported within `SecureShare.jsx`. Verify that WebRTC connection states are torn down gracefully on unmount to prevent memory leaks in the broader vault.
* [x] **Organization (Settings):** Convert the individual tab components (`AccountTab`, `SecurityTab`, `IntegrationsTab`, etc.) into an array of lazy-loaded configurations mapped to a single `<SettingsTabContainer>` rather than hardcoding imports for all 6 tabs simultaneously.

### 5.5 Global Components & Services Consolidation (`components/`, `services/`)

* [x] **Viewers Cleanup:** The `components/ui/viewers/` directory contains 9 separate files (`NoteViewer`, `PasswordViewer`, `WalletViewer`, etc.). Reduce this to a single `components/ui/DynamicViewer.jsx` that uses a registry or switch statement to render the appropriate interior data mapping.
* [x] **Service Refactoring:** Audit `services/vault.js`, `services/firestoredb.js`, and `lib/crypto/index.js` to ensure the Layered Architecture is intact. UI components (like `Button.jsx` or `Fab.jsx`) must never import crypto or db services directly; all interactions must route through the `VaultContext.jsx` or specific domain hooks.
